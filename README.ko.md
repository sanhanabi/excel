# ExcelAssistant

> 4B급 로컬 모델을 내장한 Windows용 독립 실행형 Excel 도우미

[English README](README.md)

ExcelAssistant는 자연어 요청을 제한된 Excel 작업 계획으로 바꾸는 완성된 Windows 스탠드얼론 프로그램입니다. 배포판에는 Python 런타임, Qwen3.5 4B 양자화 모델과 llama.cpp 실행 환경이 함께 들어 있습니다.

일반 사용자의 설치 과정은 다음이 전부입니다.

```text
배포 파일 받기 → 압축 풀기 → ExcelAssistant.exe 실행
```

Python, Ollama, 별도의 모델, API 키와 인터넷 연결이 필요하지 않습니다.

## 스탠드얼론 배포판 다운로드

완전 오프라인 배포판에는 4B 모델이 포함되어 있어 GitHub의 파일당
Release 용량 제한보다 큽니다. 따라서 `v1.0.0`은 두 개의 압축파일
조각으로 제공합니다.

1. [ExcelAssistant v1.0.0](https://github.com/sanhanabi/excel/releases/tag/v1.0.0)을 엽니다.
2. 다음 세 파일을 같은 폴더에 다운로드합니다.
   - `ExcelAssistant-v1.0.0-win64.zip.001`
   - `ExcelAssistant-v1.0.0-win64.zip.002`
   - `Install_ExcelAssistant.cmd`
3. `Install_ExcelAssistant.cmd`를 더블클릭합니다.
4. 생성된 `ExcelAssistant-v1.0.0` 폴더에서
   `ExcelAssistant.exe`를 실행합니다.

설치 CMD는 Windows 기본 기능으로 두 조각의 SHA-256을 확인하고, 파일을
합친 뒤 완성된 ZIP도 다시 확인하고 압축을 풉니다. Python, Ollama,
7-Zip이나 모델 서버를 별도로 설치하지 않습니다.

배포 EXE는 코드 서명 인증서로 서명되어 있지 않습니다. 따라서 Windows
SmartScreen이나 회사 보안 프로그램에서 경고할 수 있습니다. GitHub
Release의 파일명과 `SHA256SUMS.txt`를 확인하고, 회사 PC에서는 조직의
보안 정책을 따라야 합니다.

## 공개 배포 목적

이 저장소를 공개하는 목적은 완성품 판매가 아니라 다음과 같습니다.

- 로컬 LLM이 자연어를 제한된 실행 계획으로 바꾸고 검증된 코드가 실행하는
  구조를 포트폴리오와 기술 사례로 공개
- 다른 개발자가 함수 카탈로그를 추가하거나 모델·추론 엔진을 교체할 수
  있도록 소스와 빌드 방법 제공
- 엑셀 자동화, 로컬 AI와 안전한 도구 실행을 연구하거나 개선하려는 사람이
  MIT 라이선스 범위에서 코드를 수정·재배포할 수 있게 함

배포판은 실제 사용 가능한 기준 구현이지만, 특정 회사의 업무 규칙을 모두
대신하거나 상용 기술 지원을 보장하는 제품을 뜻하지는 않습니다.

## 왜 만들었는가

사용자는 엑셀에서 얻고 싶은 결과를 알고 있어도 그 결과를 만들기 위한
함수, 필터, 피벗 테이블이나 VBA 사용법까지 알지는 못할 수 있습니다.
기존 자동화 방식만으로는 이 간격을 완전히 해결하기 어렵습니다.

- 고정 매크로는 파일 구조와 열 이름이 예상과 같을 때만 효율적입니다.
- 자유로운 AI 코드 생성은 잘못되거나 위험한 작업을 만들어낼 수 있습니다.
- 회사 데이터를 외부로 보낼 수 없는 환경에서는 클라우드 AI를 사용하기
  어렵습니다.
- 관리되는 회사 PC에는 Python, 모델 서버와 개발 도구를 설치하기 어렵거나
  금지되어 있을 수 있습니다.

ExcelAssistant는 자연어 이해와 실제 실행을 분리하기 위해 만들었습니다.
로컬 모델은 사용자가 해결하려는 문제를 해석해 제한된 계획을 제안하고,
일반 코드는 등록된 작업만 검증하고 실행합니다.

## 기존 엑셀 자동화와의 차이

| 방식 | 일반적인 한계 | ExcelAssistant |
|---|---|---|
| 수동 엑셀 작업 | 함수, 필터와 피벗 사용법을 알아야 함 | 일상적인 자연어로 요청 |
| VBA 또는 고정 매크로 | 정해진 파일 구조에 종속되기 쉬움 | 선택한 파일을 분석해 실제 열과 요청을 연결 |
| 자유로운 AI 코드 생성 | 임의 코드를 만들거나 실행할 수 있음 | 모델은 등록된 작업만 선택 가능 |
| 클라우드 AI 지원 | 업무 데이터가 PC 밖으로 전송될 수 있음 | 계획과 실행이 모두 로컬·오프라인에서 동작 |
| 고정 목적 자동화 | 미리 정한 처리 흐름만 지원 | 검증된 여러 작업을 순서가 있는 계획으로 조합 |
| 확인 없는 AI 실행 | 잘못된 해석을 실행 후에 발견할 수 있음 | 실행 전 계획, 열, 조건과 예상 결과를 표시 |

이 프로젝트를 한 문장으로 표현하면 다음과 같습니다.

> ExcelAssistant는 AI가 Excel을 직접 조작하게 하지 않습니다. 로컬 모델이
> 사용자의 문제를 제한된 계획으로 번역하고, 검증된 코드가 그 계획만
> 실행합니다.

## 설계 전제

이 프로젝트는 소형 로컬 모델을 실행 주체로 신뢰할 수 없다는 전제에서 출발했습니다.

모델은 Python 코드를 작성하거나 실행하지 않습니다. 등록된 48개의 Excel 작업 중에서 실행 계획만 제안합니다. 프로그램은 함수명, 열, 매개변수, 실행 순서와 실행 가능 여부를 검사한 뒤 사용자에게 계획을 보여줍니다.

```text
Excel 원본
    ↓
주 데이터 영역 탐지
    ↓
로컬 4B 모델이 제한된 작업 계획 제안
    ↓
함수 계약과 실행 가능 여부 검사
    ↓
메모리상 복사본에서 미리 실행
    ↓
사용자 확인
    ↓
pandas/openpyxl의 결정론적 함수 실행
    ↓
새 결과 워크북 저장
```

검증기는 선택한 표나 업무적 의미가 사용자의 실제 의도와 같은지까지 판단한다고 주장하지 않습니다. 의미에 대한 최종 판단은 실행 전 확인 단계에서 사용자가 내립니다.

## 16GB RAM과 4B 모델을 사용하는 이유

처음에는 8GB RAM과 2B급 모델을 목표로 실험했습니다. 실제 시험 결과 2B 모델은 기본적인 Excel 용어와 작업 의도조차 안정적으로 해석하지 못했습니다.

그래서 실제 최소 지원 기준을 다음과 같이 변경했습니다.

- 최소 메모리: 16GB RAM
- 내장 모델: Qwen3.5 4B 양자화 모델
- 전용 GPU: 필요 없음
- 운영체제: Windows 10/11
- 네트워크: 필요 없음

이는 홍보를 위한 저사양 표현이 아니라 실제 시험 결과로 정한 최소 기준입니다.

## 스탠드얼론 사용 방법

1. 배포 파일의 압축을 완전히 풉니다.
2. `ExcelAssistant.exe`를 실행합니다.
3. 하나 이상의 `.xlsx` 또는 `.xlsm` 파일을 선택합니다.
4. 자동으로 탐지된 주 데이터 영역이 맞는지 확인합니다.
5. 한 가지 작업 또는 순서가 분명한 여러 작업을 입력합니다.
6. **작업 내용 확인**을 누릅니다.
7. 열 연결, 조건, 실행 순서와 예상 행 수를 확인합니다.
8. 계획을 승인하고 새로운 결과 파일명을 지정합니다.

첫 번째 계획은 내장 모델을 시작하느라 수 분이 걸릴 수 있습니다.

실제 열 이름과 셀 값을 사용하면 가장 안정적입니다.

```text
지점별로 금액 합계를 구하고 큰 순서로 정렬한 다음
맨 아래에 전체 합계 행을 추가해줘
```

## 원본 보호

- 입력 워크북은 저장하거나 덮어쓰지 않습니다.
- 결과 경로를 원본 파일 경로와 같게 지정할 수 없습니다.
- 계획과 미리보기는 메모리상 복사본에서 실행합니다.
- 결과는 새로 생성한 워크북에 기록합니다.
- 자동 테스트에서 실행 전후 원본 파일 바이트가 같은지 확인합니다.
- 계획 또는 실행이 실패해도 원본 파일은 변경되지 않습니다.

원본 데이터, 검증용 복사본과 결과 데이터를 분리해서 보유하는 것도 모델 출력을 신뢰하지 않는다는 동일한 설계 원칙에 따른 것입니다.

## 지원 작업

현재 등록된 작업 함수는 48개입니다.

- 주 데이터 영역 자동 탐지
- 여러 파일과 시트 결합
- 빈 행, 중복, 결측값과 문자열 정리
- 열 선택, 삭제, 재정렬과 이름 변경
- 숫자, 날짜, 문자와 불리언 자료형 변환
- 단일 조건과 중첩된 AND/OR 필터
- 상대 날짜 필터와 최신 기록 선택
- 그룹 합계, 평균, 개수와 다중 집계
- 피벗, 순위, 상하위 N개, 누계와 증감률
- 사칙연산 열과 날짜 차이 열
- 필수값 누락, 오류값과 중복 표시
- 숫자 형식, 행·셀 강조와 색상 스케일
- 소계, 전체 합계와 조건부 요약 수식
- 숨겨진 행 포함·제외 처리

모든 작업은 `DataFrame + 검증된 매개변수 → 새로운 DataFrame` 형태로 실행됩니다.

## 스탠드얼론 구성

배포판은 다음 구조를 가집니다.

```text
ExcelAssistant.exe
config.json
models/
└── planner.gguf
runtime/
└── llama/
    ├── llama-server.exe
    └── llama.cpp 실행에 필요한 DLL
Python 런타임과 프로그램 의존성
LICENSE
THIRD_PARTY_NOTICES.md
licenses/
```

프로그램은 임시 localhost 포트에서 Web UI를 끈 `llama-server.exe`를 내부 추론 엔진으로 실행합니다. 계획 생성이 끝나면 서버를 종료합니다. 프로그램이 비정상적으로 종료된 경우에도 서버가 메모리에 남지 않도록 Windows Job Object로 수명을 묶습니다.

## 공개 소스 범위

이 저장소는 포트폴리오 검토와 기술 평가를 위한 프로그램 소스와 테스트를 담습니다. 용량이 크거나 실행 중 생성되는 다음 항목은 Git에 올리지 않습니다.

- 2.87GB GGUF 모델
- 컴파일된 실행 파일과 Python 런타임
- llama.cpp 바이너리
- 실제 테스트 워크북과 결과 파일
- 로컬 작업 계획 로그

일반 사용자가 실행하는 대상은 소스 체크아웃이 아니라 스탠드얼론 배포판입니다.
기본 [`config.json`](config.json)은 Ollama가 아니라 실제 스탠드얼론의 내장 llama.cpp 서버 구조를 사용합니다.

동일한 개발 환경과 배포 폴더를 준비하는 방법은
[`BUILDING.ko.md`](BUILDING.ko.md)에 정리되어 있습니다.

## 검증

```powershell
py -m unittest discover -s tests -v
```

현재 자동 테스트 143개가 통과합니다. 표 탐지, 원본 불변, 실제 셀 값 기반 필터, 중첩 조건, 집계, 수식, 서식, 모델 컨텍스트 한도, 재시도와 내장 llama.cpp 통신 구조를 검사합니다.

## 제한사항

- 결과는 원본을 직접 편집하지 않고 새로운 표로 생성합니다.
- 기존 차트, 피벗 테이블, 도형, 매크로와 전체 워크북 레이아웃은 복사하지 않습니다.
- 여러 독립 표가 배치된 보고서형 시트보다 하나의 주 데이터 표가 있는 시트에 적합합니다.
- 미리보기가 실제 업무 의도와 맞는지는 사용자가 판단해야 합니다.
- 기본 설정에서는 작업 로그를 기록하지 않습니다. 개발자가 진단 로그를
  명시적으로 켜면 요청과 계획 정보가 로컬 `logs/plans.jsonl`에 기록될 수
  있습니다.
- 8GB RAM과 2B 모델은 지원 대상이 아닙니다.
- `v1.0.0` 배포판은 지원이 종료된 Python 3.9.9 런타임으로 빌드되었습니다.
  런타임 업그레이드는 후속 버전의 유지보수 항목입니다.

## 개인정보

워크북 내용은 내장 로컬 모델과 로컬의 결정론적 코드에서만 처리되며 외부 AI 서비스로 전송되지 않습니다.

배포판의 `logging.enabled` 기본값은 `false`입니다. 로그를 직접 활성화한
경우에는 사용자 요청과 선택된 계획이 포함될 수 있습니다.
